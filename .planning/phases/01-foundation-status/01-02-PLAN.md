  <name>Task 1: Implement data layer — sessions, stuck detection, and queue parsing</name>
  <files>gsd</files>
  <action>
Add data functions to the existing `gsd` file in the "Data Functions" section (between formatting and subcommand functions per the architecture).

**`get_sessions()` function:**
- Run `opencode session list --json 2>/dev/null` and cache result in a variable (§6.1, §10.10 — single call, reused)
- Validate output is valid JSON array: `printf '%s' "${json}" | jq -e 'type == "array"' &>/dev/null`
- If opencode fails or returns invalid JSON, print debug message and set empty array `"[]"`
- Store in a global variable `SESSION_DATA` so it's called once per invocation
- Handle empty sessions gracefully (§2.1.10)

**`get_running_sessions()` function:**
- From `SESSION_DATA`, use jq to filter sessions that appear to be running/active
- NOTE: We don't know the exact opencode session list JSON schema yet. Use a reasonable jq filter like: `jq -r '.[] | select(.status == "running" or .status == "active")' or fall back to showing all sessions if no status field
- Return JSON array of running sessions
- If no running sessions, return empty array

**`check_stuck()` function — implements §5 (all):**
- Takes a session name/PID as argument
- Checks PID file at `"${LOG_DIR}/gsd-${session}-pid"` (§5.2, §6.4)
- If PID file exists:
  - Read PID from file
  - Check if alive via `kill -0 "${pid}" 2>/dev/null` (§5.3)
  - If dead: remove stale PID file silently (§5.9), return "not_running"
  - If alive: get runtime via `ps -o etimes= -p "${pid}" 2>/dev/null` (§5.4)
  - Check log staleness: `stat -c %Y "${LOG_DIR}/gsd-${session}.log" 2>/dev/null` (§5.5)
  - Compute staleness: `$(( $(date +%s) - log_mtime ))`
  - If missing log file: treat as potentially stuck if runtime > threshold (§5.6)
  - Mark stuck if BOTH: runtime > threshold AND (log stale > 300 seconds OR no log) (§5.1)
- Return status string: "running", "stuck", or "not_found"
- Print runtime and staleness via printf to be captured by caller

**`get_queue_items()` function:**
- Read `"${QUEUE_FILE}"` (§6.3, §9.2)
- If file doesn't exist: debug message, return empty (don't error — status should still work)
- Parse sections: track current section via `## ` headers (§2.2.4): "In Progress", "Queued", "Done", "Failed"
- Parse task lines: regex `^- \[([ xX])\] (.+)$` to extract checkbox state and description (§2.2.3)
- Use section headers to determine status, NOT checkbox state (a `- [ ]` in "In Progress" is in-progress)
- Handle malformed lines: skip silently (§2.2.7)
- Output format: one line per item as `status|name|description` (pipe-delimited for easy parsing)
- Use `while IFS= read -r line; do ...; done < "${QUEUE_FILE}"` (not pipe-to-while — Pitfall #2)

**`get_completed_sessions()` function:**
- From `SESSION_DATA`, extract completed/finished sessions
- Sort by completion time (most recent first), limit to 5 (§2.1.4)
- Return JSON array

**Important implementation notes:**
- ALL `local var; var=$(cmd)` pattern (Pitfall #4)
- ALL variables quoted (Pitfall #1)
- Process substitution `< <(cmd)` not `cmd | while` (Pitfall #2)
- Guard arithmetic against zero with `|| true` where needed (Pitfall #3 — set -e)

**Formatting helpers (add to Formatting Functions section):**

`print_header()` — takes a label string, prints it bold+blue with a dim separator line below:
```
printf '%s%s%s\n' "${BOLD}${BLUE}" "$1" "${RESET}"
printf '%s%s%s\n' "${DIM}" "$(printf '%.0s─' {1..60})" "${RESET}"
```

`print_table_header()` — takes field widths and names, prints bold header row + dim separator.

`truncate_str()` — takes string and max_width, returns truncated with `…` if too long. Use `${str:0:$((max-1))}…` pattern.

**`cmd_status()` implementation:**

1. **Gather data:**
   - Call `get_sessions` (populates SESSION_DATA)
   - Call `get_running_sessions` → parse into arrays
   - For each running session, call `check_stuck` to determine stuck status
   - Call `get_queue_items` → parse into arrays
   - Call `get_completed_sessions` → parse into arrays
   - Count: running, stuck, queued, completed

2. **JSON output mode (`JSON_OUTPUT=true`)** — §2.1.8, §3.5:
   - Build JSON object with jq using `--arg` and `--argjson` for safety
   - Structure: `{ "timestamp": "ISO8601", "summary": { "running": N, "stuck": N, "queued": N }, "sessions": { "running": [...], "stuck": [...] }, "queue": [...], "completed": [...] }`
   - Timestamp: `date -u +"%Y-%m-%dT%H:%M:%SZ"` (§3.5.2)
   - Use `jq -n` to construct (not string concatenation — that's fragile)
   - Print to stdout and return

3. **Compact view (default)** — §2.1.6:
   - Print a summary header line: `"📊 GSD Status"` (or just "GSD Status" with bold)
   - Print summary counts: `"${GREEN}N running${RESET}  ${RED}N stuck${RESET}  ${YELLOW}N queued${RESET}"`
   - If any running sessions: print brief list (session name + duration + stuck indicator)
   - If any stuck: highlight in bold red
   - If any queued: print count or first 3 names
   - Last completed: print last 3 as one-liners (name + pass/fail)
   - Handle empty state: if no sessions AND no queue items, print friendly message: `"No active sessions. Queue is empty. All clear!"` (§2.1.10)

4. **Verbose view (`VERBOSE=true`)** — §2.1.7:
   - Print full table for running sessions: columns SESSION | STATUS | PID | DURATION | LOG ACTIVITY
   - Use `printf` with fixed field widths (§3.2.1): `%-20s %-8s %-8s %-10s %-15s`
   - Bold table headers (§3.2.3), dim `─` separators (§3.2.4)
   - Truncate session names with ellipsis if >20 chars (§3.2.2)
   - Color rows by status: green=running, bold+red=stuck, yellow=queued, dim=completed (§3.1.6)
   - Print full table for queued items
   - Print full table for last 5 completed

**Empty state handling:**
- No running sessions → "No running sessions"
- No stuck → don't show stuck section at all
- No queue items → "No queued items" (not an error)
- No completed → "No completed sessions"

**Performance:**
- Call `opencode session list` exactly once (§2.1.9, §10.10)
- All processing via bash builtins + jq, minimize subshells
- Target < 2 seconds total (§2.1.5)
